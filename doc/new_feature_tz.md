# Техническое задание: Добавление расшифровки звонков и анализа диалога в административную консоль

## 1. Цель
Реализовать отображение расшифровки телефонных звонков и анализа диалога в веб-интерфейсе административной консоли для повышения прозрачности и контроля качества обслуживания.

## 2. Описание функциональности

### 2.1. Отображение расшифровки звонка
- В журнале звонков (`/calls/log`) добавить колонку **"Расшифровка"**.
- Колонка отображает статус обработки:
  - "Ожидает" — если `transcription_status = 0`
  - "В обработке" — если `transcription_status = 0`, но `transcription_id` задан
  - "Готово" — если `transcription_status = 1`
  - "Ошибка" — если `transcription_status = -1`
- По клику на статус открывать модальное окно с:
  - Полной текстовой расшифровкой (`transcription`)
  - Структурированным диалогом (`dialog`)
  - Возможностью прослушать запись

### 2.2. Поиск по содержанию звонков
- Добавить поле поиска в журнале звонков.
- Поиск должен искать по:
  - Тексту расшифровки (`transcription`)
  - Диалогу (`dialog`)
  - Имени абонента
- Использовать фильтрацию на стороне сервера.

### 2.3. Статус обработки в отчётах
- В отчётах по звонкам (`/report`) добавить сводку по статусам расшифровки.
- Отображать количество звонков:
  - Без расшифровки
  - В обработке
  - Успешно расшифрованных
  - С ошибками

### 2.4. Управление пользователями
- Интерфейс уже реализован в `/users`
- Использует таблицу `users` MariaDB
- Поддерживает:
  - Фильтрацию по отделу
  - Добавление/редактирование/удаление
  - Экспорт/импорт CSV
  - Хеширование паролей (bcrypt + MD5 для Asterisk)
- Интеграция с Asterisk через перезапуск сервиса
- Телефон пользователя (Users.phone) используется как ID в таблицах Asterisk

### 2.4. Управление абонентами Asterisk
- Интерфейс реализован в `/users` (BluePrint `users_bp`)
- Данные хранятся в таблицах MariaDB:
  - `ps_endpoints` — конфигурация SIP-устройств
  - `ps_aors` — параметры адресации
  - `ps_auths` — аутентификация
- Используется связка по телефону (Users.phone = ID в ps_* таблицах)
- Настройка через `extconfig.conf` с ODBC-драйвером
- Перезагрузка конфигурации через `/users/restart/asterisk`

## 3. Технические требования

### 3.1. Модель данных
- Таблица `calls` уже содержит необходимые поля:
  - `transcription: Text`
  - `transcription_status: Integer`
  - `transcription_id: String(255)`
  - `dialog: Text`
- Изменения в схеме БД не требуются.

### 3.2. Интеграция с сервисами
- Расшифровка выполняется внешними сервисами:
  - `app_snd_trns` — отправка на расшифровку
  - `app_rcv_trns` — получение результата
- Веб-интерфейс только отображает данные.

### 3.3. Интерфейс
- Добавить иконку расшифровки в строку звонка.
- Использовать Bootstrap Modal для отображения текста.
- Реализовать подсветку найденных фраз при поиске.

### 3.4. Управление пользователями
- Интерфейс реализован в `/users` (BluePrint `users_bp`)
- Данные хранятся в таблицах MariaDB:
  - `users` — пользователи веб-интерфейса

### 3.5. Управление абонентами Asterisk
- Интерфейс реализован в `/users` (BluePrint `users_bp`)
- Данные хранятся в таблицах MariaDB:
  - `ps_endpoints` — конфигурация SIP-устройств
  - `ps_aors` — параметры адресации
  - `ps_auths` — аутентификация
- Используется связка по телефону (Users.phone = ID в ps_* таблицах)
- Настройка через `extconfig.conf` с ODBC-драйвером
- Перезагрузка конфигурации через `/users/restart/asterisk`
