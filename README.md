# saas_call_center
## MVP - проверка возможности как SAAS решения

## Функции:
- Организация внутренней связи в офисе
- Протоколирование звонков
- Карточка клиента
- Транскрибация телефонного звонка
- Выставление категории звонка по тексту звонка ???
- Анализ разговора для определения проблемных звонков

## Структура системы

### app_ami
Сервис подключается по AMI протоколу к asterisk и получает события о звонках. События фильтруются, выбираются только события о начале, окончании и файле записи разговора. Выгранные события отправляются в очередь событий звонков rabbitmq, для дальнейшей обработки.

### app_call
Сервиc получает события из очереди и формирует информацию о состоянии звонка в redis. Получив последнее событие об окончании звонка сервис формирует сообщение о звонке и отпправляет его в очередь свершившихся звонков rabbitmq.

### app_db
Сервис получает сообщение из очереди о свершённом звонке и сохраняет его в БД. БД может распологаться где угодно, в том числе и у клиента.

### app_new_call
Сервис получает событие о начале звонка, дополняет её информацией о звонящем из БД заказчика и отправляет подписчикам в web socket. Эта информация используется клиентом в сплывающем окне с информацией о звонящем.

### app_snd_trns
Сервис получает сообщение из очереди о свершённом звонке и получает из поля `record_file` имя файла записи разговора и отправляет его в yandex_speech для транскрибации, в ответном сообщении получем ID задания сохраняет его в поле `transcription_id`.

### app_rcv_trns
Сервис получает сообщение из очереди об отправленных заданиях на транскрибацию с уникальным `transcription_id`, Проверяет окончание транскрибации, если готово сохраняет результат в поле `transcription`, а в поле `dialog` результат в форме диалога.

### app_client
Web консоль, для управления системой и для просмотра журнала звонков

### app_pm
Сервис мониторинга сервисов:
- работает в виде сервиса ОС
- слушает порт 8888 и принимает команды на управление
- проверяет статус
- запускает если требуется
