## Структура системы

### app_ami
Сервис `app_ami` предназначен для подключения к серверу Asterisk по протоколу AMI и получения событий о звонках. Он фильтрует события, выбирая только события о начале, окончании и файле записи разговора. Затем он публикует эти события в обменнике RabbitMQ для дальнейшей обработки.

#### Функции

- `event_listener(event, **kwargs)`: Обрабатывает события, полученные от сервера Asterisk. Если событие соответствует белому списку событий, вызывает функцию `publish_event(event)`.
- `publish_event(event)`: Публикует событие в обменнике RabbitMQ. Если возникает ошибка подключения к RabbitMQ, вызывает функцию `setup_rabbitmq()` и повторно публикует событие.
- `setup_rabbitmq()`: Устанавливает соединение с RabbitMQ и объявляет обменник событий.
- `run()`: Запускает сервис `app_ami`. Устанавливает соединение с RabbitMQ, подключается к серверу Asterisk и начинает прослушивание событий.

### app_call
Сервиc получает события из очереди и формирует информацию о состоянии звонка в redis. Получив последнее событие об окончании звонка сервис формирует сообщение о звонке и отпправляет его в очередь свершившихся звонков rabbitmq.

### app_db
Сервис `app_db` предназначен для сохранения информации о звонках в базе данных. Он получает сообщения из очереди `calls` и сохраняет их в таблице `calls` базы данных.

#### Функции

- `run()`: Устанавливает соединение с RabbitMQ и начинает прослушивание очереди `calls`.
- `callback(ch, method, properties, body)`: Обрабатывает сообщение из очереди `calls`. Если сообщение успешно сохранено в базе данных, подтверждает получение сообщения. В противном случае, отклоняет сообщение и отправляет его обратно в очередь.
- `store_to_db(body)`: Сохраняет информацию о звонке в базе данных. Если сохранение прошло успешно, возвращает `True`. В противном случае, возвращает `False`.

#### Структура базы данных

Таблица `calls` содержит следующие поля:

- `id`: Уникальный идентификатор звонка (автоинкремент).
- `caller`: Номер звонящего.
- `callee`: Номер вызываемого.
- `caller_id`: Идентификатор звонящего.
- `callee_id`: Идентификатор вызываемого.
- `call_start`: Время начала звонка.
- `call_end`: Время окончания звонка.
- `call_status`: Статус звонка.
- `record_file`: Имя файла записи разговора.
- `transcription_id`: Уникальный идентификатор транскрибации.
- `transcription_status`: Статус транскрибации.
- `transcription`: Транскрибация разговора.
- `dialog`: Диалог разговора.

### app_new_call
Сервис `app_new_call` предназначен для обработки событий о начале звонка. Он получает события из очереди RabbitMQ и формирует информацию о звонке, включая информацию о звонящем из базы данных заказчика. Затем он отправляет эту информацию подписчикам через WebSocket.

#### Функции

- `event_parse_and_route(body)`: Обрабатывает события, полученные из очереди RabbitMQ. Если событие соответствует определенным условиям, вызывает соответствующую функцию для обработки события.
- `callback(ch, method, properties, body)`: Обрабатывает сообщение из очереди RabbitMQ. Вызывает функцию `event_parse_and_route(body)` для обработки события.
- `run()`: Запускает сервис `app_new_call`. Устанавливает соединение с RabbitMQ и начинает прослушивание очереди событий.

### app_snd_trns
Сервис `app_snd_trns` предназначен для обработки сообщений о свершенных звонках. Он получает сообщения из очереди RabbitMQ и отправляет файлы записи разговора в Yandex Speech для транскрибации. Затем он сохраняет уникальный идентификатор задания транскрибации в базе данных.

#### Функции

- `download_file(record_file, save_path)`: Скачивает файл записи разговора по ссылке и сохраняет его в указанном пути.
- `upload_file_to_yos_bucket(file_path, object_name)`: Загружает файл в Yandex Object Storage и возвращает публичную ссылку на файл.
- `recognize_audio(record_file)`: Отправляет запрос на распознавание речи в Yandex Speech и возвращает уникальный идентификатор задания транскрибации.
- `poll_and_process_records()`: Основная функция для периодического опроса базы данных и обработки записей о звонках.

### app_rcv_trns
Сервис `app_rcv_trns` предназначен для проверки статуса транскрибации и обновления информации о звонках в базе данных. Он периодически проверяет статус транскрибации и обновляет записи в базе данных.

#### Функции

- `check_transcription_status(transcription_id)`: Проверяет статус транскрибации по уникальному идентификатору задания.
- `update_transcription_status(transcription_id, status, result, dialog)`: Обновляет статус транскрибации и результаты в базе данных.
- `poll_and_update_transcriptions()`: Основная функция для периодического опроса базы данных и обновления информации о звонках.

### app_client
Web консоль, для управления системой и для просмотра журнала звонков

### app_pm
Сервис мониторинга сервисов:
- работает в виде сервиса ОС
- слушает порт 8888 и принимает команды на управление
- проверяет статус
- запускает если требуется остановивщиеся поды

```
python3 app_pm.py
```

## утилита для управлением сервисами
в папке scripts размещёна утилита (service_control.py) для:
- build - построения сервисов
- start - запуск сервисов
- stop - остановка сервисов

синтаксис команды service_control.py {comand} {service_name}:
- connamd - build | start | stop
- service - all | asterisk | app | app_ami | app_call | app_db | app_new_call | app_pm | app_rcv_trns | app_snd_trns | mariadb | redis | rabbimq

```
python3 service_control.py build all # перестроить все сервисы
python3 service_control.py start all # запустить все сервисы
python3 service_control.py stop all # запустить все сервисы
```
